## What Was Implemented

- `LocaleMiddleware` right after `SessionMiddleware`; language-cookie policy (`django_language`, 1 year, `Lax`, `Secure` = session cookie in prod)
- `POST /i18n/setlang/` (`set_language`, public, CSRF-protected, outside `i18n_patterns`):
  - only `ro` and `en` accepted
  - `next` is translated to the chosen prefix; an unsafe or missing `next` goes to `/<language>/`

- `UpdatePreferredLanguage` use case + `DjangoUserPreferences` repository, wired with `DjangoUnitOfWork` (Story 1.8 hand-off)
- `content_language()` / `localized(obj, field)` and the `{% localized obj "field" %}` tag: the only sanctioned way to read `_ro`/`_en` content
- `components/language_switcher.html` + `css/components/language_switcher.css` (shared primitive; no JS, no inline style; staff/student sizes)
- `test_translations_complete` (parses the RO `.po` file without gettext) and a `compiled_catalogues` guard fixture
- GNU gettext installed (user space, micromamba/conda-forge); `makemessages --no-wrap` / `compilemessages` work; `*.mo` git-ignored; README **Translations** section

## Deviations from Plan

- **AC 2 on `/`**: not satisfiable until Story 1.7 adds `home:index` at `/<lang>/`. The same mechanism (cookie > Accept-Language > `ro`) is proven on `/accounts/login/`. **Hand-off to 1.7:** add `GET /` → `302 /ro/` (and the Accept-Language/cookie variants) to its tests.
- **Container uses `DjangoUnitOfWork`**, not `transaction.atomic` (Story 1.8 landed first; its documented hand-off).
- **"Română"/"English" titles are translatable entries with identical `msgstr` in both languages.** They're endonyms (each name in its own language), so AC 13's entries exist but never change the text.
- **`makemessages` must run with `--no-wrap`** (README). The story's command lacked the flag.
- **Edits to other stories' tests** (1.1, 1.2, 1.5): shim removal and language-aware assertions, required because their assumptions depended on 1.4 not existing yet. Each change is commented.
- **Extra tests**: cookie precedence, `<html lang>` per prefix, RO→EN and EN→RO, unchanged-preference no-write, full sign-out/sign-in journey, middleware order, tag autoescape, parser self-tests.

## Lessons Learned

1. Django's `translate_url` depends on the *active* language. A language switch must resolve `next` in the language of its own prefix.
2. Compiling catalogues for the first time is a test of every earlier test: assumptions that "the page is English" surface immediately.
3. Generated files need a fixed format (`--no-wrap`) as a project convention, or any tool that reads them becomes fragile.
